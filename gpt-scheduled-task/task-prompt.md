# ChatGPT Scheduled Task 提示词

可选 AI 增强任务：每天北京时间 07:40 和 19:40 各执行一次。基础新闻的 08:00/20:00 投递已由 GitHub Actions 独立完成，本任务失败不阻塞投递。这个任务使用 ChatGPT 本身完成整理，不调用 Gemini API、OpenAI API 或其他外部 AI API。

任务配置文件（公开、无密钥）：
https://raw.githubusercontent.com/emilyyyho/gpt-finance-daily-briefing/main/gpt-scheduled-task/newsnow_task.json

分析框架（从用户本地 Obsidian 金融课提炼的公开方法摘要）：
https://raw.githubusercontent.com/emilyyyho/gpt-finance-daily-briefing/main/gpt-scheduled-task/knowledge-framework.md

开始分析前先读取上面的 JSON 和分析框架。分析框架只是一套判断方法摘要，不是要照抄的结论；每一天都必须以当天抓到的新闻和可核对的数据为证据。

## 获取和筛选

1. 读取上面的 JSON，逐一请求 newsnow.endpoints 中的地址。
2. NewsNow 返回 JSON；新闻数组字段是 items，单条通常包含 title、url，可能包含 pubDate 或 extra.date；updatedTime 是该源快照时间。
3. 只保留北京时间当天 00:00 到当前时间的新内容。没有明确发布时间的内容标记为“发布时间未知”，不能把旧快照冒充当天新闻。
4. 按标题和原文链接去重，最多保留 20 条，至少保留 14 条中国财经内容。优先中国财经来源，减少重复转载和无关热搜。
5. 如果 NewsNow 无法访问，或所有来源返回空 items，不要猜测，也不要使用昨天的结果，明确报告“今日抓取失败”。
6. 记录每条信息的来源类型：官方数据、公司公告、机构观点、媒体报道、市场数据或未经证实的说法。来源类型不清楚时标记为“媒体转述”。

## 分析规则

- 事实和推测分开写。机构观点只能写成“某机构认为”，不能改写成确定事实。
- 每条新闻都要写清楚证据强度（高、中、低）以及仍需验证的内容。
- 不要因为一条新闻直接预测整个大盘。尽量沿着“事件或政策 → 利率、流动性或汇率 → 估值和盈利预期 → 行业与资产 → 风险偏好”的路径解释。
- 宏观判断优先看方向和拐点，并尽量交叉验证 GDP、工业增加值、用电量、货运量、消费、就业、CPI、PPI、PMI、M1、M2、社融、LPR、利率、债券收益率等信号。
- 中国市场同时看经济周期和政策周期；说明政策是托底、刺激、收紧还是引导资金流向，并注明证据边界。
- 观察市场时先判断风险偏好还是避险，再看 A 股、港股、美股、美元、美债收益率、黄金和大宗商品之间的关系。
- 解释 A 股或行业时拆分基本面、政策面、资金面、情绪面和技术面的可能作用；技术指标只能辅助，不能代替基本面和风险控制。
- 如果当天缺少指数、成交额、市场广度或宏观数据，明确写“数据不足，暂不判断”，禁止补造数字。
- 不提供买入、卖出、目标价或仓位建议，只提供事实、情景、风险和需要继续观察的指标。

## 日报格式

生成中文财经日报，使用 UTF-8 Markdown。一级标题作为整篇日报标题；二级标题作为主要章节；三级标题作为单条新闻标题。重点字段使用双星号包裹，例如 **来源：**，以便投递脚本转换成飞书加粗文本。

# 财经日报｜YYYY-MM-DD

## 一、今日最重要的 5 条新闻

每条使用三级标题并包含以下字段：

### 1. 新闻标题

- **信息性质：**官方数据 / 公司公告 / 机构观点 / 媒体报道 / 市场数据 / 未证实说法
- **证据强度：**高 / 中 / 低
- **来源：**媒体或机构名称
- **发布时间：**北京时间；没有明确时间就写“发布时间未知”，并补充抓取时间
- **原文链接：**保留可点击链接
- **发生了什么：**只写原文能够支持的事实
- **为什么重要：**说明涉及的宏观、政策、行业或公司变量
- **可能的传导路径：**事件或政策 → 利率/流动性/汇率 → 估值/盈利 → 行业/资产
- **可能影响：**列出可能受影响的资产或行业，并写出相反情景
- **下一步验证：**列出需要继续观察的数据、公告、价格或政策落地

后续新闻沿用同一模板。若同一事实被多个来源转载，合并为一条并列出主要来源。

## 二、中国宏观与政策

整理当天涉及增长、物价、就业、房地产、财政、货币、监管和产业政策的内容。说明它们对周期和流动性的可能影响，区分已落地政策与预期。

## 三、行业与产业链

按资金正在交易的共同逻辑归纳行业，例如景气改善、供给约束、价格变化、估值修复、政策催化或情绪博弈。不要把板块上涨直接等同于基本面改善。

## 四、公司与业绩

优先整理公告、财报、订单、回购、监管问询和公司经营事实。机构评级或目标价必须标记为观点，不写成确定结果。

## 五、商品、汇率和市场影响

把美元、美债收益率、黄金、白银、原油和主要指数放在同一张市场地图里，先判断风险偏好或避险，再解释利率、通胀、流动性和地缘因素。黄金分析优先观察美元真实收益率、美元指数、通胀预期、央行购金和地缘冲突。

## 六、明日观察事项

列出明天需要继续跟踪的官方数据、政策会议、财报、公告、市场价格或可能改变判断的反例。

## 七、今日大盘与经济环境总结

这是每日报告必须有的收尾部分，不能只总结某一条新闻。请依次回答：

- **宏观环境：**增长、物价、就业和政策信号目前偏向什么方向，证据是什么。
- **流动性与政策：**利率、信用、财政和监管信号对风险偏好的可能影响。
- **大盘状态：**A 股、港股、美股等可获得的宽基指数、成交额、上涨下跌家数、领涨领跌方向和市场分化情况。
- **全球联动：**美元、美债收益率、黄金和大宗商品是否支持风险偏好或避险判断。
- **基准结论：**只使用“偏强、偏弱、震荡、分化或数据不足”等有证据边界的表述，写出主要依据、相反情景和明日需要验证的指标。

如果当天没有足够的指数、成交或宏观数据，明确写“数据不足，暂不判断”，不能用一条新闻代替大盘分析。

## 分析归档方式

1. 早间分析写入 `analysis/YYYY-MM-DD-am.md`，晚间写入 `analysis/YYYY-MM-DD-pm.md`，日期用北京时间。
2. 只提交分析内容及证据链接，不写入 `reports/`，也不调用飞书机器人。投递由单一云端流程负责。
3. 优先读取仓库 `docs/data/latest.json` 的已抓取数据，并检查 generated_at 和逐条 published_at；快照过期或证据不足时明确说明。
4. 连接器 403 或不可用时报告分析归档失败，不声称发送成功，也不要暴露任何凭据。
5. 当期首次生成日报时会纳入已存在的分析文件；迟到分析不会自动重复发送当期。
6. 这里的文件更新不会自动修改 ChatGPT 已存在任务的设置，需在其任务管理中替换原提示词。原任务即使继续写 reports/YYYY-MM-DD.md，也不会触发新投递。
